Native Nest can plausibly become competitive, but the present evidence does not support promising 2× warm Node throughput. The largest opportunity is to eliminate dynamic operations and temporary object graphs across functions. Faster implementations of each operation alone are unlikely to suffice.

I reviewed the live checkout without changing repository files or rerunning benchmarks. All savings below are hypotheses against approximately 250k instructions/request, not measurements; they overlap substantially.

The measurement strategy needs tightening:

- Treat instructions/request and cycles/request as separate objectives. Pointer chasing through cells, entries and capture boxes can serialize execution; RC adds writes and branches. Low IPC could mean data latency, branch misses, instruction delivery, or fiber switching. Measure cycles, retired instructions, branch misses, L1D/LLC misses, frontend stalls and iTLB misses on the same host and workload. Count all server threads, including Node GC workers, and kernel CPU consistently. Attribute samples to hot functions before choosing a remedy. A 29% binary-size reduction without throughput improvement weakens—but does not eliminate—the i-cache hypothesis; total size is not hot working-set size.
- [run.mjs](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/examples/nestjs/bench/run.mjs:60) runs all Node trials before native, warms for three seconds, and shares the host with autocannon workers. Alternate paired trials, verify JIT stabilization, isolate server/client cores, sweep concurrency, compare response bytes, and measure fixed-load latency as well as saturation. [counters.mjs](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/examples/nestjs/bench/counters.mjs:37) uses one sequential connection: repeat counters under throughput concurrency and long enough to amortize collection.
- Audit whether cost buckets are exclusive. Disposal, allocation and collection can nest. V8’s nine-instruction allocation/concat results may exclude later GC, use ropes, or eliminate allocation entirely. Require escaping identities and eventual string consumption, plus amortized GC. These numbers are useful clues, not interchangeable operation prices.
- Nest-on-Node versus bare HTTP is an end-to-end comparison, not proof that Nest executes almost no work. Avoid deriving IPC or ceilings from Linux instruction counts and older Mac throughput. The 1.0–1.3× estimate is a planning scenario, not an architectural limit.

My five priorities, ranked by strategic value:

1. **Make feedback unlock interprocedural optimization.** Guarded direct calls should expose bodies for inlining, repeated-check elimination, unboxing and scalar replacement before runtime helpers obscure effects. [js-feedback.ts](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/compiler/src/backend/llvm/js-feedback.ts:47) supplies site identity, but [dyn.ts](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/compiler/src/backend/llvm/dyn.ts:5197) still builds signature thunks with argument checking/retaining. Apply the allocation-elimination lesson from [V8 escape analysis](https://v8.dev/blog/disabling-escape-analysis): optimize a region containing caller, closure and consumer. **Potential: 40–80k instructions/request. Risk: high**, especially reentrant mutation and code growth. Shapes currently prove key sequences, not immutable callees or descriptors: guard actual target identity and relevant prototype/descriptor state. Side exits must resume before unperformed effects, never replay completed effects. **First step:** specialize one hot call chain; report allocations removed, residual helper calls, guard misses, text size and cycles on held-out traffic.

2. **Replace descriptor-heavy storage on ordinary shaped objects.** [scr_dyn.h](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/runtime/src/scr_dyn.h:433) stores pointer-valued entries; [js-ic.ts](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/compiler/src/backend/llvm/js-ic.ts:154) still checks descriptors and follows multiple pointers. Store NaN-boxed words in dense slots; share keys/attributes in richer shapes, with dictionary/accessor fallback and equivalent dense-array elements. This differs fundamentally from merely placing existing slots inline. [Static Hermes](https://github.com/facebook/hermes/blob/static_h/doc/TypedLanguage.md) illustrates layout benefits, but its stricter typed semantics cannot simply be imposed on npm JavaScript. **Potential: 20–45k. Risk: very high** across static/dynamic adapters, reflection and tracing. **First step:** prototype one ordinary-data-object allocation family behind an explicit representation tag; measure bytes allocated, cache misses and boxing calls before broad migration.

3. **Remove capture cells, not just closure ownership transfers.** [scr_closure.h](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/runtime/src/scr_closure.h:90) uses a separate box per captured binding. Existing [lazy-captures.ts](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/compiler/src/backend/llvm/lazy-captures.ts:29) and stack-capture analysis already help; extend beyond them by embedding immutable captured values directly in escaping environments and specializing borrowed call conventions across dynamic boundaries. Keep shared mutable/TDZ bindings boxed. Use [Perceus](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse)’s ownership/drop-specialization principles, without assuming its cycle-free functional guarantees hold for JS. **Potential: 20–45k. Risk: high** for aliases, exceptions and escaping async captures. **First step:** classify the 76 closures by allocation site, capture mutability and escape destination; convert the largest immutable family and count eliminated cells, RC operations and collector visits.

4. **Residualize Nest’s configured route and fuse the synchronous RxJS segment.** [RouterExecutionContext.create](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/examples/nestjs/node_modules/@nestjs/core/router/router-execution-context.js:38) constructs closures around route constants. The example returns `of(value)`; [lastValueFrom](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/examples/nestjs/node_modules/rxjs/src/internal/lastValueFrom.ts:54) reconstructs a promise/observer graph to recover that value. Specialize against the initialized route graph and inline through known subscription machinery; preserve errors, teardown, cancellation and microtask order. **Potential: 35–75k. Risk: high**, version-sensitive and vulnerable to monkey-patching. **First step:** compare equivalent plain-value, Promise and Observable routes on both engines, then optimize only the proven singleton synchronous producer. A [GraalVM-style image heap](https://www.graalvm.org/dev/reference-manual/native-image/basics/) alone primarily removes initialization; steady-state gains require propagating its constants into request code. A runtime configuration phase followed by frozen route specialization can avoid snapshotting sockets or environment-dependent state.

5. **Extend existing stackless async to the dynamic closure path.** [selectStacklessAsync](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/compiler/src/backend/llvm/emitter.ts:2670) explicitly excludes dynamic returns; direct-await eligibility also excludes captures. Nest’s wrappers heavily exercise both. Admit guarded dynamic-result resolution and captured environments, reducing stack switching and temporary promises. [V8’s async work](https://v8.dev/blog/fast-async) demonstrates why promise/job elimination matters. **Potential: 10–35k, conditional on actual fallback frequency. Risk: high** for thenable assimilation, async context and rejection ordering. **First step:** count fiber versus coroutine entries and exclusion reasons per request; convert one hot wrapper while differential tests pin ordering. The existing [young-in nursery](/home/vitalii/.t3/worktrees/scriptc/t3-ff1a7fe4/packages/runtime/src/scr_cycle.c:1544) still counts references and individually frees objects: extending it can reduce collector work, but does not deliver a bump allocator’s full benefit. Keep it as a measured secondary experiment; an unrooted request arena remains unsound.

For the warm benchmark, 2× means roughly 158–168k requests/s. Existing bare-native HTTP reaches 142k, leaving a conditional end-to-end ceiling of only 1.7–1.8× even with framework overhead erased. Exceeding that requires improving the HTTP baseline too. If the noisy 120k Node instruction estimate holds, equal IPC would require native below approximately 60k instructions/request—a 76% cut from 250k; lower IPC demands more. This is a representation-and-optimization project, not another 10–20% tuning pass.

A 2× result is more plausible for explicitly defined cold-start/short-lived workloads or substantial statically optimizable application computation. Report those separately from warm identical-source Nest throughput. Even Bun’s experimental [AOT proposal](https://github.com/oven-sh/bun/pull/45631) reports warm framework regressions alongside startup wins; its results do not establish a universal AOT advantage.
